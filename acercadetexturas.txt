================================================================================
          ANÁLISIS DE CALIDAD Y PIXELADO DE TEXTURAS (shirt.gltf)
================================================================================

Este documento explica de forma detallada por qué las imágenes cargadas desde
'adminRenders.html' se ven con baja calidad (pixeladas o con dientes de sierra)
al aplicarse sobre el modelo 3D 'shirt.gltf' en 'pr.html', a pesar de que la
imagen original esté en perfecta calidad.

--------------------------------------------------------------------------------
1. DIAGNÓSTICO PRINCIPAL: FILTRADO DE TEXTURAS EN EL MOTOR 3D (WEBGL / THREE.JS)
--------------------------------------------------------------------------------
El motor de renderizado de <model-viewer> utiliza Three.js y WebGL por debajo.
Cuando se aplica una textura dinámica usando la función `createTexture(url)` en
'pr.html':

  - En el archivo original 'shirt.gltf', el modelo viene preconfigurado con un
    muestreador (sampler) optimizado:
      * "magFilter": 9729 (LINEAR - Interpolación lineal bilineal, que suaviza la imagen al acercarse)
      * "minFilter": 9987 (LINEAR_MIPMAP_LINEAR - Interpolación trilineal usando Mipmaps, que suaviza la imagen al alejarse)

  - El problema: Cuando se genera una textura dinámicamente con `viewer.createTexture(url)`,
    <model-viewer> crea un nuevo objeto de textura en memoria que NO hereda de
    forma automática los filtros optimizados definidos en el JSON del .gltf original.

  - En su lugar, la nueva textura se inicializa con los parámetros por defecto de
    WebGL o de la API de model-viewer. Si el filtro de magnificación (magFilter)
    o de minificación (minFilter) se establece por defecto en NEAREST (9728) o
    similar, WebGL no realizará interpolación suavizada entre píxeles, mostrando
    los píxeles "en crudo" (pixelados/bloques rígidos) como se observa en la
    imagen adjunta del logo de 'GYM'.

--------------------------------------------------------------------------------
2. RELACIÓN DE ASPECTO Y MAQUETACIÓN UV (DENSIDAD DE PÍXELES)
--------------------------------------------------------------------------------
El mapeado UV de la camiseta ('shirt.gltf') define qué área de la imagen de textura
se proyecta sobre cada parte de la tela:

  - La textura original de la camiseta ('shirt.png') es un lienzo cuadrado de 1024x1024 píxeles.
  - En esta plantilla de textura, la zona destinada para el estampado frontal de la camiseta
    (donde se coloca el logo o diseño) suele ser un recuadro muy pequeño de unos
    pocos cientos de píxeles.
  - Al subir una imagen que solo contiene el logotipo a Cloudinary y aplicarla
    directamente sobre el material completo, la imagen se estira o se mapea
    según las coordenadas UV de la camiseta completa.
  - Al estirar un logotipo pequeño sobre una superficie 3D grande, si no hay un
    filtro de suavizado activo (como LINEAR) y un nivel alto de anisotropía,
    la densidad de píxeles es insuficiente para la distancia de la cámara,
    generando el efecto pixelado.

--------------------------------------------------------------------------------
3. ¿HAY COMPRESIÓN EN CLOUDINARY?
--------------------------------------------------------------------------------
La función `uploadToCloudinary` en 'utils.js' sube la imagen al preset configurado.
Por defecto, Cloudinary no le reduce drásticamente la calidad al archivo original
subido (secure_url mantiene el formato original como PNG o JPEG de alta resolución).
Por tanto, el origen del problema NO es Cloudinary ni tu imagen cargada, sino la
forma en que el visor 3D la dibuja en pantalla (WebGL Sampler Filters).

--------------------------------------------------------------------------------
4. CÓMO SE PODRÍA SOLUCIONAR (SUGERENCIA DE CÓDIGO - SIN MODIFICAR TU PROYECTO)
--------------------------------------------------------------------------------
Para que las texturas recuperen su nitidez óptima y un suavizado profesional,
se deberían configurar los filtros del sampler directamente en el script de
'pr.html' al momento de aplicar la textura en `window.applyTexture`.

Actualmente en 'pr.html' (línea 674) tienes:
```javascript
if (tex && tex.sampler) {
    tex.sampler.setRotation(0);
    tex.sampler.setOffset({ u: 0, v: 0 });
    tex.sampler.setScale({ u: 1, v: 1 });
}
```

Para solucionarlo, se podría cambiar a:
```javascript
if (tex && tex.sampler) {
    tex.sampler.setRotation(0);
    tex.sampler.setOffset({ u: 0, v: 0 });
    tex.sampler.setScale({ u: 1, v: 1 });

    // Forzar filtros de suavizado lineal e interpolación de alta calidad
    // 9729 corresponde a LINEAR (Suave al hacer zoom)
    // 9987 corresponde a LINEAR_MIPMAP_LINEAR (Suave a la distancia)
    if (typeof tex.sampler.setMinFilter === 'function') {
        tex.sampler.setMinFilter(9987);
    }
    if (typeof tex.sampler.setMagFilter === 'function') {
        tex.sampler.setMagFilter(9729);
    }
}
```

Además, si quisieras aún más nitidez en ángulos oblicuos, se podría incrementar
el filtrado anisotrópico de Three.js (que por defecto viene en 1) accediendo al
objeto de textura subyacente de Three.js que model-viewer expone internamente.

================================================================================
CONCLUSIÓN: Tu imagen original está perfecta. El pixelado ocurre puramente en
el renderizado del navegador porque la nueva textura dinámica pierde los filtros
de suavizado originales del modelo GLTF. Configurando los filtros "minFilter" y
"magFilter" del Sampler como lineales (LINEAR) en la carga se resuelve por completo.
================================================================================
